今日の問い


経営者は、「ぎりぎりの赤字」を「ぎりぎりの黒字」に変えているか


赤字・減益・予想未達は、株価や経営者の評価に大きく響きます。

もし経営者が会計上の判断（引当金・減価償却・費用の計上時期など）で利益を少しだけ動かせるなら、
ゼロのすぐ手前にいる会社ほど、ゼロのすぐ上に移ろうとするはずです。

利益調整（earnings management）：会計基準の範囲内で、経営者が判断の余地を使って報告利益を動かすこと。粉飾（違法）とは区別する。 「動かせるのは少しだけ」なので、影響が見えるのはベンチマークのすぐ近くだけ、という点がこの方法の出発点。

予想してください（隣と2分）

日本の上場企業の「利益 ÷ 期首総資産」の分布を描くと、ゼロの前後はどうなっているでしょうか。

① なめらか（ゼロの前後で特に変化はない）
② ゼロのすぐ左（わずかな赤字）が少なく、すぐ右（わずかな黒字）が多い
③ ゼロのすぐ左が多く、すぐ右が少ない
④ ゼロのところに会社が集中している（ちょうどゼロが多い）


もう1問：赤字回避・減益回避・予想未達回避のうち、ゆがみがいちばん大きいのはどれだと思いますか。

挙手で集計する。②が多数派になるはず。答えは②。ただし「どれくらいはっきりしているか」は第3部まで引っ張る。 2問目は意見が割れるはず。赤字回避と答える人が多いと思われるが、このデータでは予想未達回避のゆがみがいちばん大きい。理由を考えさせておく（想定解：予想は経営者自身が出した約束なので、届かないと信用を失う。赤字に比べて、予想との差は小さな調整で埋められる）。 ④を選んだ人がいたら良い視点。ちょうどゼロの会社はほとんどない（このデータで数十社）。

期首総資産と前期の利益をつける

df <- df |>
    arrange(日経会社コード, 決算期) |>   # 会社ごとに、決算期の順に並べる
    group_by(日経会社コード) |>           # 会社ごとに計算する
    mutate(
        連続     = (決算年 - lag(決算年) == 1) & (決算月 == lag(決算月)),  # 前の行が「ちょうど1年前」か
        期首資産 = if_else(連続, lag(資産合計), NA_real_),                # 前期末の総資産
        前期利益 = if_else(連続, lag(親会社利益), NA_real_)               # 前期の当期純利益
    ) |>
    ungroup()
  • lag() ＝ 1つ前の行の値（ここでは前期）
  • group_by() があるので、別の会社の値を前期として使わない

前の行がちょうど1年前でなければ NA にします。
データが飛び飛びの会社で、2年前の値を「前期」にしてしまう事故を防ぎます。

第5回の lag() の使い方と同じ。違いは「連続」のチェックを足したこと。 問い：決算月を変更した会社（3月決算→12月決算）はどうなるか。想定解：決算月が変わった年は連続が FALSE になり、期首資産が NA になる。変則決算の年は比べられないので、外すのが正しい。

3つの比率を作る

d <- df |>

第2部：分布アプローチ

Burgstahler and Dichev (1997) の発見

考え方

  1. 利益調整がなければ、利益の分布はなめらか
  2. 経営者が赤字を嫌うなら、わずかな赤字の会社がわずかな黒字に移る
  3. すると分布にゼロのすぐ左に谷、すぐ右に山ができる

3つのベンチマーク

分析 ゼロの意味
① 赤字回避 利益 = 0
② 減益回避 前期と同じ利益
③ 予想未達回避 予想とぴったり同じ


米国企業で、①②どちらにもゼロでの段差が見つかりました。
「誰が・どの手段で調整したか」はわかりません。わかるのは分布のゆがみという状況証拠です。

Burgstahler, D. and I. Dichev (1997) Earnings management to avoid earnings decreases and losses, Journal of Accounting and Economics 24: 99-126. ③の予想（アナリスト予想）を基準にした分析は Degeorge, Patel and Zeckhauser (1999)。日本では経営者自身が予想を出す（決算短信の業績予想）ので、③は経営者予想で行う。

ヒストグラムで「段差」を見る

# 階級幅 bw のヒストグラム。ゼロの直前（-bw 以上 0 未満）と直後（0 以上 bw 未満）に色をつける
hist_bd <- function(x, bw = 0.005, lim = 0.1, xlab = "") {
    x <- x[!is.na(x) & abs(x) < lim]                       # 表示範囲（±lim）だけ使う
    tibble(bin = floor(x / bw)) |>                          # 何番目の階級に入るか
        count(bin) |>
        mutate(mid = (bin + 0.5) * bw,                      # 階級の真ん中の値
               区分 = case_when(bin == 0  ~ "ゼロの直後",
                                bin == -1 ~ "ゼロの直前",
                                TRUE      ~ "その他")) |>
        ggplot(aes(x = mid, y = n, fill = 区分)) +
        geom_col(width = bw * 0.95) +
        geom_vline(xintercept = 0, linetype = "dashed") +
        scale_fill_manual(values = c("ゼロの直後" = "#e3439e", "ゼロの直前" = "#879dde",
                                     "その他" = "grey75")) +
        labs(x = xlab, y = "企業・年度数", fill = NULL)
}
  • 階級幅 bw = 0.005：期首総資産の 0.5% ごとに区切る
  • floor(x / bw)：0 以上 0.005 未満は 0 番目、−0.005 以上 0 未満は −1 番目の階級になる

geom_histogram() でも描けるが、階級の境目がちょうど 0 になるように自分で区切っている。境目が 0 からずれると、赤字と黒字が同じ棒に混ざってしまう。 ちょうど 0 の会社は「0 以上」なので直後の階級（黒字側）に入る。

段差の大きさを測る：標準化差分

階級 i の度数を n_i、全体の度数を N、割合を p_i = n_i / N とすると、

\text{標準化差分}_i = \frac{n_i - \dfrac{n_{i-1}+n_{i+1}}{2}}{SD_i},\qquad SD_i=\sqrt{N p_i(1-p_i)+\tfrac14 N(p_{i-1}+p_{i+1})(1-p_{i-1}-p_{i+1})}

  • 分子：実際の度数 − 両隣の平均（なめらかなら期待される度数）
  • 分母：その差のばらつき（標準偏差）

直前で大きなマイナス（谷）、直後で大きなプラス（山）なら、ゼロで段差がある。
絶対値が 1.96 を超えたら 5% 水準で「なめらかではない」。

両隣の平均を「期待される度数」とするのは、分布がなめらかなら隣どうしはほぼ直線でつながるはず、という考え方。 分母は二項分布の分散から来ている。細かい導出は不要。「z値と同じように読める」とだけ伝える。

標準化差分を計算する関数

# ゼロの直前（bin = -1）と直後（bin = 0）の標準化差分
bd_test <- function(x, bw = 0.005, lim = 0.1) {
    x <- x[!is.na(x) & abs(x) < lim]
    n <- table(factor(floor(x / bw), levels = floor(-lim / bw):(floor(lim / bw) - 1)))  # 階級ごとの度数
    N <- sum(n)
    p <- n / N
    sdiff <- function(b) {                     # 階級 b の標準化差分
        i <- as.character(b); l <- as.character(b - 1); r <- as.character(b + 1)
        sd <- sqrt(N * p[i] * (1 - p[i]) + 0.25 * N * (p[l] + p[r]) * (1 - p[l] - p[r]))
        unname((n[i] - (n[l] + n[r]) / 2) / sd)
    }
    tibble(階級       = c("ゼロの直前", "ゼロの直後"),
           度数       = as.integer(n[c("-1", "0")]),
           期待度数   = c((n["-2"] + n["0"]) / 2, (n["-1"] + n["1"]) / 2),
           標準化差分 = c(sdiff(-1), sdiff(0)))
}

2つの関数 hist_bd() と bd_test() を作っておけば、あとは変数を入れ替えるだけで3つの分析ができます。

関数の中身を全部理解する必要はない。入力（x）と出力（直前・直後の度数と標準化差分）がわかればよい。 AIに頼むなら「Burgstahler and Dichev (1997) の標準化差分を、ゼロの直前と直後の階級について計算する関数」と書けば同じものが返ってくる。ただし階級の区切りが 0 から始まっているかは自分で確かめる。

2問目の予想の答え合わせ。赤字回避を選んだ人が多かったはず。 日本の決算短信の経営者予想は、達成しやすいように保守的に出される傾向があると言われる。そうなると「実績を動かした」のか「予想を動かした」のか、分布だけでは区別できない。

3つを並べると

3つとも、直前が谷（マイナス）、直後が山（プラス）。点線（±1.96）を大きく超えています。
日本企業でも、Burgstahler and Dichev (1997) と同じゆがみが見つかりました。

ライブ分析の発展課題（bw = 0.01）をやったペアがいれば、ここで発表してもらう。 学生に「どの数字が本当の答えか」と聞く。どれも正しく計算されている。

なぜ、数字が変わるのか

  • 階級幅を広げると、1つの階級に入る会社が増える → 標準化差分は大きくなる
  • 観測数（年数・会社数）が増えても同じ。だからライブ分析の1年分では小さかった

標準化差分は「何社が調整したか」の大きさではありません。
データの量と、自分で決めた階級幅で変わる数字です。

標準化差分は z 値と同じく、「段差がゼロではない」ことの確からしさ。段差の大きさ（何社が移動したか）ではない。 階級幅を広げると、ゼロの直前の階級に「わずかな減益」以外の会社（そこそこの減益）も入るので、谷が薄まる。直後の山は、0 ちょうど〜わずかな増益に集まった会社をまとめて数えるので高くなる。 Durtschi and Easton (2005) は、そもそも分布のゆがみが「規模で割ること」や「サンプルの選び方」だけでも生じうる、と批判している。分布アプローチは強力だが、状況証拠である。

グラフには段差があり、検定は星3つ。
それでも、階級幅を変えると谷は消えた。


第5回の裏切りは「変数の時点を取り違えると、回帰は正反対の結論を出す」でした。

今日はその続きです ── 分析者が自分で決めた数字（階級幅・表示範囲・規模の基準）で、結果は動く。

だから研究では、1つの設定だけで結論を出さない。複数の階級幅・別の規模の基準でも同じ結果になるか（頑健性）を確かめて報告します。

③予想未達回避の山は、どの階級幅でも残った。①の谷も残った。②の谷だけが不安定。こう整理できると、「どの結果を信じてよいか」が言える。 頑健性（robustness）は、卒業研究でも必ず聞かれる。

まとめ

今日おぼえたこと

  • 利益調整が「少しだけ」なら、影響はベンチマークのすぐ近くにだけ現れる
  • 利益分布アプローチ：ゼロの直前に谷、直後に山があれば、利益調整の状況証拠
  • 標準化差分：実際の度数と、両隣の平均（期待度数）との差を、ばらつきで割ったもの
  • 日本企業でも、赤字回避・減益回避・予想未達回避の3つでゆがみが見つかった。いちばん大きいのは予想未達回避
  • 分布のゆがみからは「誰が・どの手段で」はわからない。予想そのものを控えめに出している可能性もある
  • 階級幅などの「自分で決めた数字」を変えても同じ結果になるか（頑健性）を確かめる

今日の道具

道具 何をするか
group_by() ＋ mutate(lag()) 会社ごとに前期の値（期首総資産・前期の利益）を取る
if_else(連続, lag(x), NA) 「ちょうど1年前」でなければ前期の値を使わない
floor(x / bw) 値を階級幅 bw ごとの階級番号に変える
hist_bd(x, bw, lim) ゼロの直前・直後に色をつけたヒストグラム（今日作った関数）
bd_test(x, bw, lim) ゼロの直前・直後の標準化差分（今日作った関数）
group_by() ＋ group_modify() 年度ごとに同じ分析を繰り返す

全部覚える必要はない。AIに頼めば書いてくれる。 ただし「階級の境目が 0 になっているか」「前期は本当に1年前か」を確かめるのは、AIではなく自分の仕事。
